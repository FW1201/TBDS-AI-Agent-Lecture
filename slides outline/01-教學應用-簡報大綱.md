# AI Agent 教學實踐應用初探｜簡報內容大綱

> 使用方式：本文件可直接交給 Claude 生成簡報。請依「投影片文字」製作頁面，將「講者備註／操作」放入講者備註；案例資料請使用學生資料包中的教學情境。這份簡報供兩個班級重複使用，主體內容、活動與評量相同。
>
> 建議 3 小時、約 24 頁。受眾為台灣課程脈絡的國高中教師；語言使用繁體中文，畫面簡潔、具校園工作感，避免把 AI 畫成全自動決策者。所有學習者作品和校務資料均為合成情境。

## 投影片 1｜封面

**投影片文字**
- AI Agent 教學實踐應用初探
- 從課程資料夾到教案、學習材料與形成性回饋
- 東莞台商子弟學校｜Codex 實作課

**講者備註／操作**：先說明今天不是只練提示詞，而是讓 Agent 在一個有資料、有技能、有邊界的專案資料夾中完成可檢查的工作。

## 投影片 2｜今天要帶走什麼

**投影片文字**
- 會把任務拆成 Prompt、Context、Harness
- 會在 Codex workspace 中找到、整理和使用課程檔案
- 會讓 Agent 依 skill 與 context 產出教學材料
- 會檢查來源、正確性、學生適切性，再由教師決定是否採用

**講者備註／操作**：成果不是「按一下就有完美教案」，而是教師能有效分派、檢查和修訂 Agent 的工作。

## 投影片 3｜從檔案開始：教師每天面對的材料

**投影片文字**
- 課綱、教案、簡報、學習單、評量規準散落在不同資料夾
- 同一份材料可能有草稿、舊版和修訂版
- Agent 的價值在於跨檔案讀取、整理、比對、編輯和產出
- 教師仍需決定哪些來源可信、哪些內容適合學生

**講者備註／操作**：展示學生資料包中混亂的檔名和子資料夾；不先替學員整理，讓大家體會真實起點。

## 投影片 4｜課堂路線

**投影片文字**
- 認識 Prompt、Context、Harness 和 Agent
- 下載並盤點 GitHub 資源包
- 設定課程 workspace，整理 skill、context 和案例檔案
- 讓 Agent 產出教案／學習材料
- 覆核、修訂、交付

**講者備註／操作**：提醒學員每一步都會看到 Agent 操作專案檔案；先觀察它如何讀，再檢查它改了什麼。

## 投影片 5｜Prompt、Context、Harness：一個協作模型

**投影片文字**
- Prompt：要做什麼、給誰用、遵守什麼條件、交付什麼
- Context：課綱、單元目標、範例、規準、校內規則
- Harness：workspace、檔案權限、工具、skills、檢查和核准點
- 少一項，就容易得到流暢但不適用的內容

**講者備註／操作**：用「請幫我做教案」作模糊指令，逐步補上年級、目標、時間、材料和驗收方式。

## 投影片 6｜Agent 與一般對話有何不同

**投影片文字**
- 一般對話：主要依目前訊息生成回答
- Agent：能在授權範圍內讀檔、規劃步驟、使用工具、建立或修改檔案
- 每次工具操作都可能改變專案狀態
- 需要限制工作範圍、先看變更、再驗收結果

**講者備註／操作**：以 Codex 實際介面展示讀取目錄、檢視文件、建立輸出檔的操作；避免承諾未開通的功能。

## 投影片 7｜Workspace 是工作桌，不是萬用資料桶

**投影片文字**
- 專案資料夾提供 Agent 的工作脈絡
- 把課程指示、參考資料、輸入和輸出分開
- 指定 Agent 可讀取與可編輯的範圍
- 不放帳密、真實學生個資或未核准資料

**講者備註／操作**：展示課程 workspace 建議目錄：resources、skills、context、projects、output。說明本課使用合成資料。

## 投影片 8｜從 GitHub 下載資源包

**投影片文字**
- 下載／clone 講師指定的 GitHub 資源包
- 記錄來源、版本／commit、日期
- 原始下載放 resources/inbox
- 先讀取清單與說明，不直接執行不熟悉的程式

**講者備註／操作**：使用已匯入的 `FW1201/tw-edu-skills` v5.0.1 副本示範；版本與 MIT 授權見 `resources/manifest.md`。學員先看檔案樹和 manifest，再將上游副本放入 workspace 的 `skills/upstream/`；不執行安裝器。

## 投影片 9｜讀懂資源包：skill 和 context 的分工

**投影片文字**
- Skill：任務步驟、輸入需求、產出格式、品質檢查
- Context：學科背景、課程目標、校內規範、用語和限制
- 範本：提供可編輯的文件或表格結構
- 資料：提供本次任務要整理的內容

**講者備註／操作**：打開 `tw-edu-lesson-plan-108/SKILL.md` 和教學 Context；請學員指出「流程」和「背景規則」各在哪裡，再挑出 T1 所需輸入。

## 投影片 10｜散亂資料不是先整理完才交給 Agent

**投影片文字**
- 先讓 Agent 盤點檔案名稱、格式、日期和內容摘要
- 要求它列出重複版、矛盾處和缺漏
- 讓 Agent 提議分類，再由教師確認
- 保留原始資料；整理和產出放到工作副本／output

**講者備註／操作**：示範先盤點，不直接大規模改名或覆寫。讓 Agent 提出檔案地圖與疑點清單。

## 投影片 11｜示範案例 T1：國中九年級社會領域通學探究

**投影片文字**
- 任務：設計 90 分鐘雙節課，探究校園周邊通學環境
- 輸入：探究目標、兩版教案、匿名路口觀察 CSV、評量規準
- 產出：流程、證據判讀問題、小組提案和形成性檢核
- 保護：不拍人臉／車牌；校外觀察須先經學校確認

**講者備註／操作**：資料包中的學生數據皆為合成值。要求 Agent 先找出 85 分鐘舊流程與 90 分鐘目標不符、拍攝車牌的隱私風險，以及觀察表重複／缺漏，再提出修訂方案。

## 投影片 12｜把教案任務說清楚

**投影片文字**
- 角色／情境：國中九年級社會領域，雙節 90 分鐘
- 目標：區分觀察、資料來源和推論，以證據支持改善建議
- 條件：30 人、6 組，可投影，個人裝置不一
- 交付：流程表、教師提問、小組任務、評量規準
- 限制：不拍可識別影像；不把模擬數據寫成真實校園紀錄

**講者備註／操作**：展示一份可複用任務卡，再逐項對照 Prompt、Context、Harness。課綱相關正式文字請授課前核對教育部／國家教育研究院現行版本。

## 投影片 13｜讓 Agent 先讀，再編輯

**投影片文字**
- 第一步：列出它讀到的檔案和資料來源
- 第二步：摘要學習目標、限制和矛盾資訊
- 第三步：詢問缺漏或提出假設
- 第四步：獲得教師確認後，建立草稿

**講者備註／操作**：用兩輪指令演示「先分析」與「再產出」；展示 Agent 讀檔清單。

## 投影片 14｜Agent 操作檔案：可見、可追溯、可回退

**投影片文字**
- 原始資料留在 input／來源資料夾
- Agent 將草稿存入指定 output
- 檔名包含案例、版本和日期
- 重要變更先比較差異，再接受

**講者備註／操作**：請 Agent 在 teaching/T1/output 建立新教案草稿；展示檔案建立位置和摘要，確認 input 原始檔未被覆寫。

## 投影片 15｜閱讀生成結果：教案對齊檢查

**投影片文字**
- 每個活動是否服務於學習目標？
- 時間加總是否合理？材料是否取得得到？
- 提問能否看見學生理解？
- 哪些說法有來源，哪些是 Agent 推論？
- 有沒有需教師補充的班級情境？

**講者備註／操作**：不要只看文字是否漂亮；請小組用檢核表圈出一項可保留、一項需修改、一項需查證。

## 投影片 16｜T2：高中一年級地理校園微氣候探究

**投影片文字**
- 50 分鐘、32 人；用合成測點資料比較時間、遮蔭和溫度
- 先找出重複測點、缺漏時間和非核實來源
- 產出資料支架版、一般版及延伸探究版
- 不由單次合成量測推論真實都市熱島

**講者備註／操作**：要求 Agent 依高中地理探究目標產出三種支架，不變更共同學習目標；教師核對課程計畫和資料限制。

## 投影片 17｜T3：高中國文學習反思形成性回饋

**投影片文字**
- 依規準閱讀匿名學習反思作品
- 引用作品中的具體經驗或文本證據
- 區分觀察、建議和待追問問題
- 不給正式成績、不推測學生個人特質

**講者備註／操作**：作品皆為合成片段。對比泛泛稱讚與依證據回饋，確認 Agent 沒有把學習歷程練習誤當正式評分。

## 投影片 18｜如何修改 Agent 的工作

**投影片文字**
- 指出具體位置和問題，不只說「再好一點」
- 補上新脈絡或限制
- 要求只修改指定部分
- 再檢查其餘內容是否被意外改動

**講者備註／操作**：示範一輪修訂：「保留目標和流程，把材料改成無網路可用，僅更新材料欄及相關時間。」

## 投影片 19｜連接器／MCP：把外部工具接進工作流

**投影片文字**
- Connector／MCP 可讓 Agent 在授權下使用外部資料或工具
- 先判斷資料是否需要離開專案資料夾
- 檢查連線帳號、可見範圍與操作權限
- 無法連線時，以核准檔案副本完成練習

**講者備註／操作**：依授課環境展示已核准的連接器；沒有可用連接器時，講解概念並繼續使用本地資料。

## 投影片 20｜Skill 是可重複使用的工作方法

**投影片文字**
- Skill 可封裝專業步驟、檢查點與輸出格式
- 使用前確認來源、版本、依賴和適用範圍
- Context 仍需由教師提供，skill 不會自動知道本班需求
- 教師的專業判斷不能由 skill 取代

**講者備註／操作**：示範在任務中明確指定 skill 檔案，要求 Agent 說明它如何套用其步驟。

## 投影片 21｜Runtime／Hooks／排程：何時讓流程自己啟動

**投影片文字**
- 觸發條件：何時開始？讀取哪些資料？
- 執行範圍：允許建立什麼草稿？
- 停止條件：遇到缺漏、矛盾或敏感資料怎麼辦？
- 核准點：哪些動作必須由教師確認？

**講者備註／操作**：以「每週整理教學反思草稿」作概念案例，只產生待審稿，不自動寄給家長或寫入正式系統。實際功能依 Codex 版本確認。

## 投影片 22｜小組實作：從資源到教學成果

**投影片文字**
- 選 T1、T2 或 T3
- 從資料包找出相關 skill、context 和輸入檔
- 指派 Agent 先盤點，再產出指定檔案
- 同儕依檢核表提出一輪修訂

**講者備註／操作**：75 分鐘；T1 建議搭配 `tw-edu-lesson-plan-108`、`tw-edu-rubric-designer`，T2 可用 `tw-edu-interdisciplinary`／`tw-edu-differentiated`，T3 可用 `tw-edu-feedback-writer`。要求記錄 Agent 讀了什麼、改了什麼、哪些地方需教師判斷。

## 投影片 23｜成果評量與教師驗收

**投影片文字**
- 任務是否符合教學目標
- 來源和假設是否標示
- 教學內容是否正確、可行且適齡
- 學生隱私是否受到保護
- 教師是否能解釋並承擔最後決定

**講者備註／操作**：同儕互評不評「像不像 AI」，而評可追溯、可教、可修正。

## 投影片 24｜收束：把一個任務變成可重複流程

**投影片文字**
- 一個清楚 Prompt
- 一組可信 Context
- 一個有界線的 Harness
- 一個可檢查的 Agent 產出
- 一位保有專業決定權的教師

**講者備註／操作**：課後任務：選一項低風險備課工作，寫出輸入、skill/context、輸出和人工檢查點。A、B 班使用相同任務和評量。
