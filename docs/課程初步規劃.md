# 東莞台商子弟學校 AI Agent 教育應用課程初步規劃

> 版本：初稿 0.1（2026-10-08）
> 對象：東莞台商子弟學校教師與行政同仁；案例以台灣國高中課程與校務流程作情境基準
> 工具：Codex 及其可用的文件、簡報、試算表工作流程
> 範圍：教學應用 1 種課程、行政應用 2 種課程；教學課程開設兩班，合計四次授課

## 一、課程設計方向

課程從「如何與語言模型協作」開始，逐步走到「如何讓 AI Agent 在有界線的專案環境中完成工作」，再以教學和校務情境實作。學員會先把 GitHub 課程資源包下載到專案資料夾，辨識其中的 skills 與 context 文件，再透過 Codex Agent 讀取這些資源，編輯應用專案並產出教學或行政內容。Prompt、Context、Harness 的概念會直接放進這個操作流程中教，不另做成脫離實作的單元。

課程中的三個概念先用以下方式說明：

| 概念 | 課程中的說法 | 練習重點 |
|---|---|---|
| Prompt | 說清楚要完成的任務、對象、限制與交付格式 | 把模糊要求改寫成可檢查的指令；要求模型說明假設與待確認事項 |
| Context | 提供完成任務所需的背景、參考檔案、資料與規則 | 選擇必要資料、標示來源和版本、避免放入無關或敏感資訊 |
| Harness | 讓模型在工作環境中安全執行任務的工具、權限、流程與檢查點 | 認識 workspace、連接器／MCP、skills、runtime／hooks，以及人工核准和驗收 |

課程以「人負責目標、脈絡、授權與驗收；Agent 負責依指示整理、生成、分析及執行可授權步驟」作為協作原則。學員會練習從 GitHub 取得資源、整理專案資料夾、指定 Agent 使用哪些 skill/context，再由 Agent 產出文件、簡報或試算表。Connectors／MCP 和排程／觸發能力依實際帳號與 Codex 環境可用功能示範；若某項功能尚未開通，使用專案內的檔案及手動流程完成同一學習目標。

### GitHub 資源包到 Agent 產出的共同操作流程

四堂課都沿用同一工作模式，依案例增加不同的輸入檔和產出格式：

1. **取得資源：**將講師提供的 GitHub 資源包下載或 clone 到 workspace 的 `resources/inbox/`，保留來源 repo、版本／commit 和下載日期。
2. **盤點檔案：**辨識 skill、context 文件、範本及資料檔，閱讀其用途、輸入需求、輸出格式和限制；不直接執行未檢查的腳本，也不把機密資料放進資源包。
3. **整理專案：**依用途把確認可用的 skill 放入 `skills/`，背景規則和參考文件放入 `context/`，案例輸入放入 `projects/<案例>/input/`，Agent 草稿和成果放入該案例的 `output/`。
4. **指派 Agent 任務：**在 Codex workspace 中說明任務、讀取的 skill/context 檔案、允許操作的資料夾、成果格式和不可自行決定的事項。Agent 先回報理解、來源和缺漏，再開始編輯。
5. **產出與迭代：**Agent 依 skill 的流程和 context 的規則，整理／編輯應用資料，輸出 document、presentation 或 sheets 成果；學員比較輸入、skill 指引和輸出，補充要求並修訂。
6. **人工驗收：**檢查內容事實、引用來源、計算、格式、個資及外部動作；只把通過檢查的成果移至交付資料夾。對外傳送、正式登錄或會改變真實資料的操作另設人工確認。

資源包的 GitHub URL 尚待課程資源提供者指定；在取得 URL 前，教材以 `resources/inbox/<resource-pack>/` 作為匯入位置和流程範例，不假設特定 repo、branch 或檔案清單。之後可用教師提供的 `tw-edu-` skills 和自製 skills 填入同一流程。

## 二、四次課程總覽

下表暫以每次 3 小時作為教材設計基準，實際時數可再調整。教學應用課程內容相同，分兩次授課；行政應用分為前後連貫的（一）（二）。

| 次序 | 課程 | 核心成果 | 資源包與 Agent 操作 | 案例 |
|---|---|---|---|
| 1 | AI Agent 教學實踐應用初探（教學應用）— A 班 | 建立教學任務的 prompt、context 與人工檢核流程 | 取得並盤點 GitHub 資源包；將 skill/context 放入教學 workspace，讓 Agent 依資源編輯教學專案 | 教學案例 T1–T3，挑選一案實作、另兩案示範 |
| 2 | AI Agent 教學實踐應用初探（教學應用）— B 班 | 與第 1 次相同教材、活動、作業和評量 | 使用相同資源包和 workspace 流程；依 A 班回饋微調帶領方式，不改變課程核心 | 同 T1–T3 |
| 3 | AI Agent 行政自動化思維應用初探（一）（行政應用） | 建立行政 workspace，完成文件與表格的受控協作流程 | 以同一資源包的行政 skills/context（或對應課程資源）為依據；Agent 從案例資料夾讀取材料，產出行政文件與追蹤表 | 行政案例 A1–A3 |
| 4 | AI Agent 行政自動化思維應用初探（二）（行政應用） | 將前次流程串成可重複使用的工作流，加入多格式產出和觸發設計 | 複用並調整前次專案結構；Agent 依 skills/context 從試算表整理資料，產出報告／簡報，再設計可人工核准的觸發流程 | 行政案例 A4–A6，並回顧 A1–A3 的流程化方式 |

### 建議單次課程節奏（3 小時基準）

1. 15 分鐘：情境導入、學習目標與資料安全提醒。
2. 35 分鐘：Prompt、Context、Harness 或本堂新概念講解。
3. 25 分鐘：講師示範 Codex 任務拆解與檢查產出。
4. 75 分鐘：學員分組實作案例，完成中間檢查與同儕互評。
5. 20 分鐘：成果分享、錯誤辨識與修正。
6. 10 分鐘：帶走模板、課後任務和回饋。

以上節奏供備課估時，可依實際課程時數縮放。

## 三、課程內容與案例

### 教學應用：3 個案例

| 編號 | 案例 | Codex 工作方式 | 交付物與檢核 |
|---|---|---|---|
| T1 | 國中九年級社會領域：校園周邊通學環境探究 | 依課程目標、舊版／修訂教案、匿名觀察表和規準，讓 Agent 找出時間、隱私和資料品質問題，再建立 90 分鐘教案 | 探究流程、證據型評量、待校方核准項；檢查合成數據有無被描述成真實校園統計 |
| T2 | 高中一年級地理／校訂探究：校園微氣候資料 | 讓 Agent 檢查合成測點 CSV 的重複、缺漏和量測限制，依同一目標產出不同程度支架 | 50 分鐘活動、圖表建議、資料限制；教師核對現行課綱和校訂課程計畫 |
| T3 | 高中國文：匿名學習反思的形成性回饋 | 提供合成作品和回饋規準，要求 Agent 依作品證據給建議並保留教師判斷 | 具體回饋樣例；不打正式成績、不推測家庭或心理狀況 |

建議每班以 T1 作完整實作，講師以 T2、T3 示範如何沿用同一套 prompt/context/checklist 思維，並讓學員選一案作課後延伸。

### 行政應用（一）：基礎文件與表格流程

| 編號 | 案例 | 主要工具類型 | 流程與成果 |
|---|---|---|---|
| A1 | 課發會校訂選修提案摘要與意向調查通知 | Document + Sheets | 讀取提案、會議草稿和調查，區分需求意向與正式選課，產出會議摘要和未核定通知草稿 |
| A2 | 課發會紀錄與行動追蹤 | Document + Sheets | 將討論、暫議、決議和待辦分開，保留來源；標示重複回覆、舊課名及授課／教室待確認事項 |
| A3 | 校訂課程成果交流日暨家長說明會 | Document + Sheets | 比對活動計畫、未核定通知、場地回覆和分工表，整理可公告事項、工作追蹤與待確認項 |

### 行政應用（二）：分析、呈現與可重複流程

| 編號 | 案例 | 主要工具類型 | 流程與成果 |
|---|---|---|---|
| A4 | 校訂課程成果交流回饋問卷分析 | Sheets + Document + Presentation | 檢查回覆代碼重複、文字尺度及樣本限制，確認規則後產出工作表、改善報告和簡報草稿 |
| A5 | 視聽教室與活動設備盤點 | Sheets + Document | 整理設備帳面數、現場數、待盤點及重複項，產出差異表和承辦人待查清單 |
| A6 | 課發會／學務工作月報與主管簡報 | Sheets + Presentation + Document | 延續會議和活動追蹤表，整理完成、進行中、待決策事項，產出多格式摘要和可追溯來源 |

行政（一）建立可靠的單次任務流程；行政（二）把多步驟工作整理成可重複範本，加入可選的 skill、連接器／MCP 與 runtime／hooks 示範。所有案例均以「草稿／分析／建議」為預設產出；寄送通知、修改正式紀錄、核准支出或排程觸發外部動作，須保留明確的人工確認點。

## 四、Codex 概念與實作順序

| 階段 | 概念 | 課程安排 |
|---|---|---|
| 1 | 語言模型互動模式 | 從 prompt 開始，加入 context，再說明 harness 如何提供檔案、工具、規則、權限和檢核點 |
| 2 | AI Agent 與 Codex | 說明 Agent 如何在多步驟任務中讀資料、規劃、使用工具、檢查結果；由學員在每一步設定可接受範圍 |
| 3 | Workspace／專案設定 | 建立課程專用 workspace；將 GitHub 資源包下載到 `resources/inbox/`，辨識檔案後整理到 `skills/`、`context/` 和案例資料夾；說明 Agent 可讀寫的專案範圍 |
| 4 | Connectors／MCP | 介紹外部服務連接與工具呼叫的用途、授權及資料流；只使用已核准服務，並在實際連接器可用時演練 |
| 5 | Skills | 直接使用 GitHub 資源包中的 skill：檢查其用途、輸入、輸出與限制，再指派 Agent 依 skill 編輯案例專案；後續將教師提供的 `tw-edu-` skills 和自製 skill 加入同一目錄及流程 |
| 6 | Runtime／Hooks／排程與觸發 | 從定時彙整或檔案／事件觸發的例子說明何時啟動、可執行範圍、紀錄與停止條件；功能依實際 Codex 版本及環境確認後再安排操作 |
| 7 | Document／Presentation／Sheets 工作流 | 讓 Agent 依專案中的 skills/context 編輯應用資料，產出文件、簡報和試算表；練習讀取、草稿生成、修訂、驗收和交付 |

授課前需確認資源包 GitHub URL、學員實際可用的 Codex 版本、連接器和 Office 檔案操作方式；教材要同時保留無連接器時可完成的檔案式流程。外掛程式和 MCP 的可用名稱依環境設定為準，教材不預設每位學員都有相同權限。

## 五、建議產出材料

### 講師備課材料

- 課程總綱：對象、先備能力、學習目標、時數、課程地圖及案例對照。
- 講師手冊：每堂流程、示範腳本、提問引導、常見錯誤、備援操作及收尾方式。
- 教學簡報：概念圖、Codex 操作步驟、案例示範、風險情境及回顧題。
- GitHub 資源包導入指南：repo 取得方式、來源版本紀錄、skill/context 盤點欄位、匯入目錄、Agent 指派範例及更新方式。
- 環境檢查表：workspace、資源包存取、檔案操作、連接器／MCP、skills、runtime／hooks 的課前確認與替代流程。
- 評量規準：任務完成度、資料正確性、可追溯性、隱私和人工覆核。

### 學員材料

- 學員講義：Prompt／Context／Harness 練習表和 Agent 任務拆解卡。
- 案例任務單：教學 T1–T3、行政 A1–A6 的情境、輸入、限制、交付物、驗收問題。
- Agent 操作卡：如何從資源包挑選 skill/context、如何界定 Agent 可讀寫資料夾、如何要求先回報理解再產出。
- 可複製模板：課程計畫、公告、會議紀錄、追蹤表、分析摘要、簡報大綱。
- 學生下載資料包：散落的虛構校務與教學材料，混合 DOCX、XLSX、CSV、PDF、EML、TXT，包含重複、舊版、矛盾、缺欄和不同格式；讓學員直接練 Agent 盤點、比較、整理及編輯檔案。
- 講師專用解讀：與學生資料包分開，列出情境來源優先序、刻意設計的資料品質問題及教學觀察點，不放進學生 ZIP。
- 自我檢查清單：事實、來源、計算、日期、敏感資料、偏誤、對外動作及人工核准。
- 課後任務與回饋表：將一個日常任務改寫為可重複的 Agent 工作流程。

## 七、資料治理與驗收原則

- 練習預設使用合成資料。若改用真實校務資料，先確認學校授權、資料最小化及服務的資料處理規範。
- 不在一般練習中輸入學生姓名、學號、成績、健康或家庭資訊，也不輸入教職員個資或帳密。
- 每份輸出標示來源檔案、假設、模型無法確認的事項及人工覆核者；統計結果保留可重算的欄位和公式。
- 對外公告、學生評量、正式會議紀錄、採購決策、權限變更和自動觸發動作都設人工核准點。
- 評量重點是流程品質與可驗證性，不以文字流暢作為正確性的替代。

## 八、下一階段建置順序

1. 確認 GitHub 資源包 repo／URL、每次課程時數、學員對象與電腦／帳號條件。
